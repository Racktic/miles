# 案例研究 4 — 训 WRITE 的两组去掉探索奖励会怎样(+ 2×2 交互)

## 名词表(先读这个)

| 词 | 意思 |
|---|---|
| **ACT / WRITE** | ACT = 玩游戏的动作流;WRITE = 每个 trial 结束后写记忆总结的流 |
| **探索奖励(β)** | 让 deepseek 给每次记忆更新打"有没有新发现"的分,乘 β 加进 ACT 的优势值。β=0.3 开启,β=0 关闭 |
| **A03 / A0** | 只训 ACT 的两组:A03 有探索奖励,A0 没有(案例3 分析过) |
| **S03 / S0** | ACT+WRITE 一起训(co-train,WRITE 奖励=downstream_norm_improve)的两组:S03 有探索奖励,S0 没有 |
| **无效动作(invalid)** | 环境拒绝执行的动作,如操作已交进锅里的石头、重用已耗尽的药水。浪费一回合但不扣分 |
| **裸动作** | 模型输出里没有思考过程(REASONING 段)、只有一行 ACTION 的回合 |
| **撞上限** | 一个 trial 用满 20 回合都没有主动喊"end the trial" |

四组其余设置完全一样:Qwen3-4B、budget 提醒 + explore_v3 提示词、记忆窗口 3。
run 名:A03=`actonly-w3-expl03-budgetv3-…0630`,A0=`actonly-w3-b0-…0701`,S03=`sig4norm-w3-expl03-budgetv3-…0630b`,S0=`sig4norm-w3-b0-…0701`。
**注意:分析时 S0 只训到 70 步(A0 到 100 步),都还在训练中。**

## 问题

案例3 发现:只训 ACT 时,去掉探索奖励(A0)会让模型"停不下来"——回合数暴涨、无效动作暴涨、eval 停滞。
本案例问:**如果本来就在训 WRITE(S 组),去掉探索奖励还会这样崩吗?**

---

## 发现 1:训了 WRITE 之后,去掉探索奖励基本不崩了

都看第 60 步,"去掉探索奖励"造成的恶化幅度:

| 恶化幅度(β0 减 β0.3) | 只训 ACT(A0−A03) | 一起训 WRITE(S0−S03) |
|---|---|---|
| 每局回合数 | **+51.5**(131.5 vs 80.0) | +9.8(101.0 vs 91.2) |
| 无效动作率 | **+16.1 个百分点**(21.2% vs 5.1%) | +1.7 个百分点(10.3% vs 8.6%) |
| 撞上限的 trial 占比 | **+15.6 个百分点**(17% vs 1.4%) | +0.6 个百分点 |
| eval(hard20 归一化分) | 拉开差距:0.32 vs 0.44 | **没有差距:0.34 vs 0.34** |

结论:**「训 WRITE」和「探索奖励」在防止行为崩坏上作用重复。** 有其中一个就基本压得住;两个都上,好处不叠加(eval 上完全看不出 β 的收益)。

另外两点值得记下:
- S0 没有像 A0 那样越崩越快:它只是每一步都比 S03 差一点点(差距稳定在 ~5-10 回合),像"S03 提前了 5 步",不是失控轨迹。
- 但 S03 自己比 A03 膨胀得快(60 步时 91 vs 80 回合)——**训 WRITE 会抬高两组的探索量/回合数**,这与 β 无关(见发现 3)。

---

## 发现 2:训 WRITE 为什么能防崩——因为"写总结"这个任务本身管住了输出习惯

先复述崩坏的过程(案例3 查明的):trial 后期模型开始输出**裸动作**(不写思考直接甩一行 ACTION);裸动作出错概率是正常动作的 **3-5 倍**;然后越错越甩,直到烧满 20 回合。裸动作率的抬升在时间上**先于**无效率的抬升,是崩坏的前兆。

四组的裸动作率(第 60 步):

| A03 | **A0** | S03 | **S0** |
|---|---|---|---|
| 7.6% | **23.9%** | 8.6% | **13.1%** |

同样没有探索奖励,S0 的裸动作率只有 A0 的**一半**。解释:WRITE 训练要求模型**每个 trial 都写一大段结构化总结**,这个写作任务的梯度维持了模型连贯输出的习惯,恰好挡住了"思考蒸发→乱甩动作"这条崩坏路径。

我们检验并**排除**了另外两种听起来合理的解释:
- ❌ "WRITE 的奖励惩罚了乱动的轨迹" —— 算了组内相关性,四组全部约等于 0,不存在这条通道;
- ❌ "训出来的记忆写得更好,模型照着记忆行动就不乱了" —— 四组记忆的长度、格式、信息密度全都一样(连不训 WRITE 的 A 组也一样),零空记忆;防崩不来自记忆内容。

还有一个"只是崩得慢,不是不崩"的怀疑:数据说是**真的减速**(S0 起跳晚 10 步、且同样恶化程度下速度只有 A0 的一半),不是单纯延迟;但 S0 只到 70 步、最终停在哪还不知道,**需要它训到 ~100 步后复查**。一个耐人寻味的旁证:S03 在 75 步左右冲高后自己回落了。

---

## 发现 3:顺带解决了之前的疑问("为什么训 WRITE 的模型探索更多")

之前讨论过 S03 比 A03 探索多的原因,我当时提过一套"记忆写手放大了探索奖励"的解释。现在的判定性证据:**连探索奖励都没有的 S0(101 回合)探索量也超过带着探索奖励的 A03(80 回合)。**

→ 探索变多是**训 WRITE 本身**带来的,与探索奖励无关。之前那套解释作废。

---

## 补充:S0 那一点点超额(+9.8 回合)是什么

它和 A0 的崩法不一样:
- A0 的标志性崩法("石头全交进锅后不喊停、对着空盘子甩裸动作到撞上限")在 **S0 和 S03 里被同等压制**(浪费 3.5-3.6 回合/局,A0 是 15.7;主动结束率都是 98.3%)——压住这个的是 WRITE 训练,不是 β;
- S0 多出来的主要是**中段的低效**:带着完整思考、但状态记错了(比如推理里说"红色药水之前没效果",然后选了一瓶早就用光的药水),重用已耗尽药水 256 次 vs S03 的 150 次;有效动作里"试了但没结果"的占一半(50% vs 45%)。

逐字例子(两组都有 A0 同款崩法,只是很少):
> S0@60 ep_3879 trial8(13 连裸无效):`ACTION: Place stone 2 in potion 2` → `ACTION: Place stone 0 in potion 6` → …
> S03@60 ep_3894 trial1(幻觉编号):`ACTION: Place stone 8 in potion 0`(局里只有 0-2 号石头)

---

## 结论

1. 防"停不下来"的崩坏,**探索奖励和 WRITE 训练是两条重复的保险**:只训 ACT 时探索奖励必不可少(案例3),训了 WRITE 后它的价值缩到很小、eval 上为零。
2. **给"为什么要训 WRITE"添了一个新理由**:哪怕记忆内容没变好(数据显示确实没有),"每 trial 写一段总结"这个任务本身就稳住了模型的行为。
3. 之前"训 WRITE 的模型探索多"的原因查清:是 WRITE 训练本身,不是探索奖励的连带效应。
4. 未定论:S0 的最终走向(训到 100 步复查)、S03 冲高回落是否持续、每格只有一次实验的运气成分。
